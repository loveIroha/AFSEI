# 原 MAC 框架的主动切线优化

本阶段优化源 Land 主动力的切线计算。流体仍是 128³ 规则 MAC 网格，
沿用原 BE–BE 隐式残差、Anderson–Newton、流体响应、多重网格、IB 传递和收敛标准。
EP 单域 PDE 仍由 PyTorch GPU 计算，GPB/Land 门控仍由现有 CUDA 内核计算。
没有新增流固外层迭代，没有改变时间步长、材料、张力公式或规定压力。

## 修改与数学等价性

原实现逐批对 135430 个单元的主动节点力进行 `vmap(jacrev)`。
现用解析单元切线，并使用原 AFSI 的 `tensor_kernel` 编译为 GPU 内核。
被动、基底和内膜规定压力的切线继续由已有组装器计算，主动项加入原 CSR 稀疏结构。

对于 P1 单元，记 `v=Ff`、`s_a=∇N_a·f`、`r=v·v`。
源主动 PK1 为 `Ta g(r) v⊗f`，其中
`g(r)=1+4.9(sqrt(max(r,1))−1)`。节点力为
`f_a=−s_a A(r) v`，`A(r)=g(r) Σ_q w_q Ta_q(r)`。
因此节点力切线为

```text
∂f_ai/∂x_bk = −s_a s_b [A δ_ik + 2 A'(r) v_i v_k]
```

`A'` 同时包含 Land 张力的伸长导数和额外 PK1 乘子的导数。
Land 内部仍使用原 `h(λ)` 截断、两个 Z 历史的精确递推、空间 XS/XW 积分和非负张力截断。
冻结卸载时 Ta 的导数为零，但 PK1 乘子与 `Ff` 的几何导数仍保留。
实现不修改任何被接受的物理历史。

截断处不可微，解析内核在启动时用一个 CPU 标量探测当前 PyTorch 的边界导数约定，
编译后按同样约定选择掩码；它不是 CPU 网格求解或 CPU 组装。
服务器 PyTorch 2.14.0 在截断边界选择常数分支。
系数与中间量保持网格 float64 精度，避免布尔掩码先与浮点常数相乘产生 float32 临时值。

## 实际 GPU 验证

服务器 RTX 4090，真实 LV 26889 节点、135430 单元，流体 128³、13 cm 外箱。
机械步长 0.1 ms，EP 0.05 ms，GPB/Land ODE 0.002 ms。

CPU/GPU 检查包括原主动力自动微分对照、独立中心差分、压缩与截断点、
剪切和非单位方向、空间积分、冻结卸载、稳定试算缓冲区、完整隐式流固步进、
失败回退、检查点重启与源规定压力预加载。
单元切线与原自动微分使用 `rtol=5e-13, atol=2e-8`；中心差分另设误差容限。
20 项回归检查全部通过；增加本次耗时字段后，再次通过运行/重启/失败发布检查。

同状态性能对照从第十阶段源压力预加载后的第 10 ms 检查点出发，
两种实现分别再推进 1 ms，均接受 10 步，无回退。
统计同步 GPU 后的驱动步耗时，分别排除首步；不计输出写盘。

| 每步均值（排除首步） | 原自动微分 | 解析并编译 |
|---|---:|---:|
| 总耗时 | 3.562 s | 1.312 s |
| 隐式流固部分 | 3.432 s | 1.199 s |
| GPB/Land | 0.0704 s | 0.0700 s |
| 单域 PDE | 0.0340 s | 0.0222 s |
| 流体求解次数 | 19 | 19 |
| 压力多重网格循环 | 192 | 192 |
| 切线组装次数 | 2 | 2 |
| GMRES 迭代 | 8 | 8 |

总耗时减少约 63.2%，约 2.72 倍加速。
首步分别 10.39 s 与 9.35 s，包含初始化、编译及冷启动，不代表稳定推进速度。
ODE/PDE 的细小计时差别不是本阶段 EP 算法修改带来的加速。
主要收益来自去除主动切线的重复自动微分并融合张量运算。

最终位移最大差异 8.88e-15 cm，电位最大差异 3.34e-15 V；
三个速度分量相对 L2 差异均低于 1.75e-11，固体节点合力相对差异 1.79e-10。
新旧路径均按原真实非线性残差接受，不依靠近似切线收敛标记跳过检查。

服务器报告：`results/phase11_tangent_benchmark_final_10_to_11ms/report.json`。

随后从同一第 10 ms 检查点再连续推进 10 ms 到第 20 ms（物理时间 0.520 s）：
新增 100 个接受步、200 个 EP 步、5000 个 ODE 子步，无回退。
排除首步后的平均步耗时 1.349 s，末段约 1.37 s；
GPB/Land 0.0701 s、单域 PDE 0.0225 s、隐式 FSI 1.2358 s。
平均每步 19.62 次流体求解、2 次切线组装、8.62 次 GMRES 迭代。
最终 Ta 最大 53604 dyn/cm²、最大流速 32.94 cm/s、腔体体积 134.833 ml，
最小 detF=0.88919；所有接受步均满足真实非线性残差。
最大散度 L2=2.43e-9，界面离散功误差最大 1.35e-6 erg/s。
结果在 `results/phase11_mac128_preloaded_20ms_v1`，含可续算 MAC 检查点。

该次报告的 `elapsed_seconds=462.174` 是包含父检查点 312.611 s 的累计时间；
本次续算约 149.562 s。今后报告在 `performance` 中额外列出
`elapsed_this_invocation_seconds` 和 `elapsed_previous_seconds`，避免将累计时间误当作本次耗时。
这些计时在发布结果前采样，步统计另行排除输出、启动与首步。

## 使用

原 MAC 入口自动使用新的主动切线，旧 MAC 检查点无需转换：

```bash
python scripts/run_afsei.py \
  --resume results/phase10_mac128_preloaded_10ms_v1/checkpoint.npz \
  --duration-ms 10 --profile --output results/my_mac_optimized_20ms
```

复现同状态对照（运行两次临时状态，不修改输入检查点）：

```bash
python scripts/check_afsei_active_tangent.py \
  --resume results/phase10_mac128_preloaded_10ms_v1/checkpoint.npz \
  --duration-ms 1 --output results/my_active_tangent_benchmark.json
```

## 循环接口仍待完成

目前 MAC 的 8 mmHg 是源心肌的规定内膜载荷，外箱压力为零；
没有基底密封约束，也没有实际瓣口和流量驱动的 RCR。
只在基底取样速度、计算流量并更新 RCR，仍会遗漏其余基底开口的泄流，不能视作完整循环耦合。

下一阶段按以下顺序完成物理接口，保持规则 MAC 网格：

1. 由现有内膜边缘建立基底封面并划分理想化 MV/AV；明确记录没有解剖瓣膜。
2. 构造封面与端口的 MAC 速度积分、压力做功算子，核对流量/载荷的离散功共轭关系。
3. 接入封面密封与关闭端口约束，验证 `dV/dt=Qin−Qout` 和非端口泄流，
   两阀关闭时验证体积约束；将这些条件纳入原隐式残差与线性化。
4. 连接真实端口流量驱动的 RCR，替换当前规定 8 mmHg 心肌载荷，并重新建立相容初态。
5. 接入实际 AV 关闭事件触发的源 80 ms 张力快速卸载，再验证完整周期及性能。

这些约束会增加工作量，需要分别计时；当前数据不能作为接入循环后的完整周期耗时。
按照 1.31–1.35 s/步、0.1 ms 步长外推两个 800 ms 周期，纯算术值约 5.8–6.0 小时，
只反映当前早期激活与固定载荷算例，未包含预加载、输出、后续强收缩和循环接口成本。
