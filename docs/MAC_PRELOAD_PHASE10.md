# MAC 源压力预加载与性能

本阶段继续使用原规则 MAC 网格、BE–BE 隐式流固残差、多重网格和 IB 传递。
新增源电–力内膜压力预加载，并保存可在 MAC 主入口续算的检查点。

## 数学模型与初态

加载期间求解 `f_passive(x) + f_endo(x,p) = 0`，压力按源程序在
0–500 ms 从 0 线性升至 8 mmHg，在 100 个 5 ms 的物理加载端点更新
CG1 伸长投影与 Land `Zs/Zw`。电位、GPB、Land 四个门控状态保持初始值。
基底积分、材料和内膜压力方向沿用已独立核对的源 UFL。
基底封口仅用于腔体体积测量，不增加封口压力载荷。

在原 AFSI 框架中，内膜规定压力属于心肌外载荷；静态时它与被动力平衡，
MAC 传播的是合力，外箱流体初始速度和表压均为零。
新参数 `prescribed_endocardial_pressure_mmhg` 默认 0，保持旧 MAC 检查点兼容。
预加载检查点保存 8 mmHg；后续时间推进保留该固定载荷，主动部分只取 EP/GPB/Land。
主动和规定压力导数均进入原 Newton 切线。

这一步没有将实际血液压力初始化成 8 mmHg，也没有连接流量驱动 RCR。
规定压力必须在未来物理端口压力反馈接入时明确替换，避免两次加载。
初始参考几何仍视作无载参考；本阶段没有反求残余应力。

除被动力平衡外，初始化还用原 MAC 求解器执行一次被动试算，检查
位移 L2 不超过 1e-9 cm、最大流速不超过 1e-6 cm/s及原非线性残差。
该试算结果丢弃，初始时间、门控、历史和速度均不推进。

## 运行

从头重新求解源 100 个加载端点：

```bash
cd /mnt/large2/gjh/AFSEI
source scripts/activate_afsei.sh
python scripts/prepare_afsei_mac_preload.py --output results/my_mac_preload_8mmhg
python scripts/run_afsei.py --resume results/my_mac_preload_8mmhg/checkpoint.npz --duration-ms 10 --profile --output results/my_mac_preloaded_10ms
```

服务器上已有第八阶段独立 UFL 核对的纯固体源预加载结果，可以避免重复静态求解：

```bash
python scripts/prepare_afsei_mac_preload.py \
  --reuse-source-preload results/phase8_source_alignment_vs_phase7_v1/source_solid_preload_bound.npz \
  --output results/my_mac_preload_from_source
```

导入对象只有源心肌位置和 `Zs/Zw`，没有流体网格或流体状态。
导入检查 SHA256、参考几何、网格/方向绑定、100 个压力/时间端点、
最终 Z 历史统计及当前源材料的真实平衡残差，然后新建 MAC 状态并进行被动试算。
已有四面体三场检查点会被拒绝。
`summary.json`、`loading_history.json`、新的 MAC `checkpoint.npz` 写入输出目录。
源结果复用不包含原先静态求解的耗时，报告明确记录 `source_result_reused`。
预加载入口可用 `--nonlinear-solver newton` 或 `anderson-newton` 选择原框架已有的模式；
选择保存在新检查点中。续算恢复原设置，不会静默切换求解器。

`run_afsei.py` 保留源预加载标记和压力设置，报告仍明确
`windkessel_ports_connected=false`、`three_field_integration_implemented=false`。
原无预加载的 MAC 入口仍可用于性能对照，旧检查点恢复自己的设置。

## 性能口径

使用真实 LV、128³ MAC、RTX 4090、流固 0.1 ms、EP 0.05 ms、ODE 0.002 ms。
`--profile` 分阶段 GPU 同步计时，步骤时间包含拒绝重试，但不含输出诊断和写盘。
各次启动的首步单独统计，可能包含图捕获或懒编译；后续平均不保证完全热身。
预加载几何与伸长历史会改变主动张力和耦合难度，所以两种初态的速度应分别报告。

预加载后仍需在 MAC 框架中接入实际瓣口、闭瓣密封、流量驱动 Windkessel，
验证真正等容/射血/充盈阶段、80 ms 卸载事件及完整心动周期。
当前固定压力短算的性能不能直接当作完整循环耗时。

## 实际 GPU 结果（2026-10-10）

21 项相关 GPU/回归检查通过，包括规定压力的编译力与切线、源加载历史、
静态漂移、检查点续算，以及此前保留的四面体预加载接口。
MAC 耦合、BE 流体、多重网格、IB 传递/组装和 PaperLV 模块与固定 AFSI_GPU 基线逐字节一致。

真实 LV 的新 MAC 预加载目录为 `results/phase10_mac128_source_preload_v1`。
本次复用第八阶段已独立核对的纯固体源加载结果；检查和 MAC 初始化耗时 18.27 s，
该耗时不包含原先求解 100 个静态加载端点的时间。
最终腔体体积 136.789324127 ml，参考体积 68.330348401 ml，
力平衡残差 1.9943e-4 dyn，容差 1e-3 dyn。

被动 MAC 试算的最大流速 1.0442e-7 cm/s，位移 L2 为零（原接受容差下），
真实非线性残差 3.5836e-10 cm，容差 1e-9 cm；试算状态未发布。

这说明原先约 0.45 s/步的初始未加载测量不能代表源预加载后的计算难度。

从同一个已预加载 10 ms 检查点分别追加 1 ms，保留相同方程、容差和步长：

| 原求解模式 | 去掉首步平均 | 流体求解/步 | 切线组装/步 | GMRES 迭代/步 |
| --- | ---: | ---: | ---: | ---: |
| Anderson–Newton | 3.580 s | 19 | 2 | 8 |
| 直接 Newton | 4.820 s | 21 | 3 | 14 |

两者最终最大位置差 3.70e-11 cm，速度相对 L2 差不超过 1.43e-8，
所有步骤通过真实残差，均无回退。直接 Newton 在本窗口更慢，因此保留原 Anderson–Newton 默认。
减少外层迭代数量并不自动减少完整流体求解及切线工作。

按每步 3.0–3.58 s、0.1 ms 步长，两个 800 ms 周期需要 16000 步，
单纯线性外推约 13.3–15.9 h（不含独立预加载、初始化和输出）。
目前只验证了早期激活、固定规定压力，尚未包含完整射血/闭瓣/充盈。
后续强收缩和真实循环接口会改变工作量，因此这个数字是当前测量的算术外推，
不是完整心动周期的实测或可靠预测。
