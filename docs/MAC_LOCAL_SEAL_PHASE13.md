# 第十三阶段：原 MAC 上的局部基底密封投影验证

本阶段保留原规则 128³ MAC 网格、开放外箱和隐式流固主入口。
新增独立的局部法向约束投影组件，验证不可压缩性、运动基底反力、压力功与动能平衡。
这不是已接入主线的瓣膜或循环模型；诊断结果不写成可续算的 FSI 检查点。

## 空间约束与数学关系

沿用第十二阶段随心肌边缘运动的基底积分封面，排除理想化 MV/AV 区域。
非端口积分点按当前 MAC 尺度分组，每点恰好属于一个局部压力区域。
边缘面积过小的碎片并入最近的有效区域，避免增加病态的小面积约束。
基底不展平，血液网格不改变；封面是边界积分面，不是贴体流体网格。

令 `B u` 为各局部区域的流体法向通量，`C w` 为同一区域的材料运动通量，
`W` 为 MAC 速度控制体积权重，包括开放箱法向边界的半控制体积。
封面支撑位于箱内，其直接压力传播使用完整体积 `h³`。
局部约束为：

```
B u_new = C w
D u_new = 0
```

以原 Dirichlet 多重网格求解器构造不可压缩投影 `P`。
先将输入投影为 `u0`，再解压力乘子的 Schur 系统：

```
(B P W^-1 B^T) mu = B u0 - C w
u_new = u0 - P W^-1 B^T mu
lambda = rho/dt * mu
```

压力每次从零初值求解，并对右端项归一化，防止绝对容差与历史初值改变线性作用。
Schur 系统用 GPU PCG 和区域 Gram 对角预条件器；每次作用需要一次原压力求解，
不重复粘性、对流、心肌或电生理推进。检查最终真实约束残差。

流体压力载荷为 `-W^-1 B^T lambda`，材料反力为 `C^T lambda`：

```
fluid_power + material_power = -lambda^T (B u_new - C w)
```

材料速度在本子问题中是规定值。包含输入散度修正与基底投影损失的动能平衡为：

```
E_new - E_input + loss_divergence + loss_cap
    + dt * (C^T lambda) : w = 0
```

这一步满足区域平均法向约束，**不保证每个积分点都不透流**。
报告同时列出区域平均残差、净泄漏、积分点泄漏绝对值之和以及法向滑移 RMS/最大值，
不能用净泄漏抵消来证明逐点密封。

## 实际 GPU 验证

服务器 RTX 4090，源预加载及首次刺激后 10、20 ms 的三个既有 MAC 检查点。
这些检查点的 SHA256 在读取前后逐一比较，原物理状态没有改写。
CPU/CUDA 测试覆盖区域划分、流固功共轭、运动封面、散度投影、压力增量符号、
动能平衡、Schur 对称性、线性作用、输入不变性及失败保护。

20 ms 状态（物理时间 0.520 s）的区域尺度对照：

| 指标 | 3 个 MAC 单元宽 | 2 个 MAC 单元宽 |

| 投影后净泄漏绝对值 | 约 2.2e-9 ml/s | 约 7.9e-10 ml/s |

| 法向滑移 RMS：投影前 | 19.251 cm/s | 19.251 cm/s |
| 法向滑移 RMS：投影后 | 2.733 cm/s | 1.596 cm/s |

加密减少积分点泄漏，但最大残余滑移仍大，不能据此发布“完全密封”结果。
运动封面压力功相对误差低于 1e-12，动能平衡相对误差约 1.3e-11。
第 10 ms 状态采用 219 个区域：净泄漏 44.464 ml/s 降至约 1.5e-11 ml/s，
积分点泄漏绝对值之和仍为 4.149 ml/s。
静止预加载状态零速度/零材料速度保持为零。

服务器报告：

- `results/phase13_mac128_seal_verified_v2/report.json`：三个状态，默认 3 单元尺度。
- `results/phase13_mac128_seal_refined_v2/report.json`：20 ms 状态，2 单元尺度。

计时包括压力约束求解、反力和能量检查，排除文件读取、几何准备、初次编译。
初始化和单次原压力求解器冷启动另列，不算入上述热运行均值。
本阶段主线步耗时没有改变，之前 1.35 s/步是未接循环的早期激活实测。
**0.62/1.11 s 是独立投影耗时，不是完整三场步耗时。**
如果将它机械地嵌套进每步约 19 次流体响应，可能产生显著额外开销；
目前没有这样修改或启用，也不能直接将其与 1.35 s 相加预测完整周期。

## 使用

在服务器现有环境中运行，输出需要新目录：

```bash
python scripts/check_afsei_mac_seal.py \
  --checkpoint results/phase11_mac128_preloaded_20ms_v1/checkpoint.npz \
  --repeats 3 --output results/my_mac_seal_check

python scripts/check_afsei_mac_seal.py \
  --checkpoint results/phase11_mac128_preloaded_20ms_v1/checkpoint.npz \
  --patch-width-cells 2 --repeats 3 --output results/my_mac_seal_refined
```

诊断修改的流体速度只存在于临时内存中，原心肌不会对基底反力重新响应。
MV/AV 仍开放且未施加单向条件；诊断后 MV 通量仍可反向。
这些通量不是可用于射血分数或生理 RCR 的完整循环结果。

## 后续主线接入的必要条件

1. 解决局部平均约束未覆盖的残余泄漏，选择空间约束基与预条件器并做分辨率对照。
   单纯收紧 PCG 容差不能消除这类空间误差。
2. 将基底压力乘子、材料反力及一致线性化纳入原隐式心肌–MAC 残差。
   可写为 `R_x=y-dt*J*u(y,lambda)`、`R_cap=B*u(y,lambda)-C*y/dt`，
   其中流体作用须包含原固体力、`C^T lambda` 和相应流体边界载荷；
   复用原流体线性响应构造块作用与预条件器，单独测额外压力成本。
   不得将本诊断速度直接覆盖已接受检查点，或丢弃基底反力。
3. 加入 MV/AV 单向阀和关闭区域约束，再验证 `dV/dt=Qin-Qout`、闭阀体积约束与实际界面误差。
4. 连接实际相对流量驱动的 RCR，替换现有规定内膜 8 mmHg 载荷并建立相容初态。
5. 以实际 AV 关闭事件触发源 80 ms 张力快速卸载，验证完整周期及耗时。

`mainline_cap_sealed`、`windkessel_ports_connected` 和完整三场标记仍为 `false`。
